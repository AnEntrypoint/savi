# Rooms and Matchmaking

Meeting is Spawn's, the same in every game: the door picks the room (`main`, the one room nearly every game needs, since a room holds nearly unlimited players), and a friend arrives through Spawn's people plate: `invite +`, `copy link`, a portal, a party's `portal together`. So a game builds no lobby, no room code or code entry, no match list or queue, and mints no invite link; asked for one, say it is Spawn's; a party or guild invite from the game's own panel is the inviting player's act; a map or mode pick before play is a pad or a doorway in the world (→game-ui). The game's own is the match inside the room it was given: sides (a party is a ready-made team: `player.party`), rounds, a ready-up and a countdown, the referee in sim.js (the match's phase, roster, score and winner), `spectating`, a scoreboard, and a copy of a place per group or per player (`instance`) when the fiction wants its own arena. When a match has a size, `routing.maxPlayers` is the whole matchmaker: the door fills rooms of that size and opens the next; `pickRoom` is for a placement rule the door cannot guess (a region, a mode), never a lobby.

```js
// scripts/routing.js: a file you write; world.config.yaml: routing: { script: scripts/routing.js, maxPlayers: 20 }.
import { mostFullWithSpace, nextRoomName } from "builtin/room-routing";

export async function pickRoom(ctx) {
  const requested = ctx.requestedRoomId; // the room Spawn's invite, portal or link names: the ticket; return it even before the room exists: the first arrival creates it
  if (requested && !ctx.rejectedRooms.includes(requested)) return requested;
  return mostFullWithSpace(ctx) ?? nextRoomName(ctx.rooms, ctx.rejectedRooms);
}
```

```js
// scripts/player.js: the game's own door into its arena: a trigger, a press, a countdown's end. sendAction lands in the CONTROLLED entity's onInput, never in a manager's.
export function onInput(ctx, input) {
  if (input.pressed["enter-arena"]) {
    const out = ctx.cross(ctx.self, "+arena"); // the copy this player or their group is or was in, else a fresh one: ctx.self.place names it; delete ctx.world.places[name] ends it
    if (!out.crossed) return ctx.emit("uiEvent", { name: "refused", payload: { message: "Couldn't open the arena: try again" } }); // refused; nothing was left behind; ui.js draws the message
  }
  if (input.pressed["start-round"]) {
    const mgr = ctx.place.objects["match-manager"];
    if (mgr && ctx.place.owner === ctx.self.id) mgr.state.phase = "playing"; // one writer per fact: the manager's state, through its handle
  }
}
```
- Routing on is the `routing` block; `maxPlayers` is ONE cap for every room of the game, enforced at the door (unset = no door, every body admitted; the pick's fill reads 20): party size is your roster, not the cap. The door counts BODIES: every player, an inhabitant agent's body included; Savi's helper body and a wisp's never take a slot, so size the cap for the players alone. A room keeps what happens in it (`routing.persistence: "persistent"`, the default): each room your rule names has its own `world.state`, clock and RNG; `main` alone is the world's shared default; `session` keeps it one room-life, from the first arrival until the room has stood empty a while; `ephemeral` drops it with the last player.
- `pickRoom` is not a behavior: no world, no database; it imports `builtin/room-routing` and its own tree's files, async allowed. It returns a room name: lowercase letters, digits, `_` and `-`, up to 64 characters. null, a throw or a bad name fall back (the player's last active room with space, else the world's own room). A full room refuses the join at the door and the pick runs again with that room in `ctx.rejectedRooms`; the player reads "room full" only when your rule names a room that already refused.
- One world, many rooms: a Write, an Edit or a run_script changes the one tree every room boots from; a behavior's `spawn`/`destroy` touches its own room only. "Clear the arena" saved as an edit from a match room empties every room, permanently: edit the authored world from the build room. What survives is an ownership question: the player's durables (prizes, inventory, progression) persist from anywhere, the most ephemeral boss room included: `player.state`, a key per room under it when rooms differ; the room's transients (arena state, live scores, leftover golems) belong to the room. `ctx.rooms[].metadata` is telemetry, never game data. `spawn room reset <name>` empties a room's transients: every runtime-placed thing dies, every moved thing returns to its tree pose, everyone in it rejoins within a second: reset `main` after a test.
- Room-wide match state has ONE writer: the manager in the match place; a second referee "repairing" the same fact from another place builds ping-pong. A state write on a `ctx.world.players` row lands on that player in any place (whole top-level keys: `row.state.queueMatch = { place, role }`, never a nested fragment); `getObject(them)` is null from another place AND when they left: branch on the row's `.place` first; what both sides must read (rosters, phase) lives on an `audience: "all"` bulletin object. A clock that must outlive an emptied place is handed to the destination manager on arrival. `routing.maxPlayers` is shared by every copy in the room: size it to matches × match size + lobby headroom; past one room's honest capacity, per-match rooms by name are the next rung. `policy.admits` runs IN the copy: `ctx.place.owner` its host (null while no copy stands), `entity` the arrival: `admits(ctx, e) { return e.id === ctx.place.owner || ctx.place.players.length < 8 }`.
- Physics your script steps itself, as a rollback or predicted mover does, runs in its own `createWorld()` world; every `builtin/physics` read takes it as its first argument.
- A world boss and its bar, a stage, or a zone circle that every player must see uses `audience: "all"` on its row.
- A world that keeps going while nobody is on (a farm producing overnight, a shop restocking, a town clock) is `routing.alwaysOn: true` (world.config.yaml or ctx.world.routing; off by default), and the word buys a visit, never a server that stays up: every 15 minutes, for 24 hours after the last player left, Spawn's own machine opens the room once, runs the crons owed since the last visit (each missed slot once, in order), ticks sim.js with the whole gap since its last run on the first tick's `ctx.gapMs`, fires the due `ctx.after` rows, saves and leaves; between visits nothing runs, and a player's return runs the world live again. So offline progress is arithmetic at the visit: `state.gold += ratePerMs * ctx.gapMs` in tick, or a cron that reads `ctx.now()` (continuous across the sleep) against the stamp it keeps in `world.state` and pays the difference: right whether it fires once or for every slot it owes; a `ctx.sql` read in tick or a cron costs one call per visit. A singleplayer world is not visited: the time nobody watched arrives on its player's next open as the same `ctx.gapMs`. Tell the creator what they get: the world catches up every 15 minutes for a day after the last player, and picks up live the moment someone is back.

- Porting a multiplayer game: adapt its rules to the supported game API. Move the hero with `ctx.self.velocity` in `onInput`/`update`, put enemy movement in its behavior, and write hits to the target's state. Carry over speeds, accelerations, dash and swing timings, wave rules, scoring, and data tables as `scripts/lib/data/*.yml` rows. Spawn has no server-authoritative movement or custom networking code; coins or a bag a cheater must not edit are `platformState` keys →platform-systems.
