# Jayzee implementation gaps for the documented featureset

Source of status: jayzee `docs/PARITY.md` at `6cb503a` (jayzee's latest committed PARITY, equal to origin/main). The 66 ranked rows and their status words are taken from that file, not from the working tree. Each jayzee path cited in a row is checked by `scripts/check-featureset.mjs` to exist at that pin. Existence is not behaviour. A row marked built means jayzee's own gate, as written in its PARITY.md, passes. This register does not re-run jayzee's gates.

Tags:
- required-in-jayzee: jayzee's PARITY.md marks the row partial or open. The open clause is quoted, and it is the implementation queue.
- none (built): jayzee's PARITY.md marks the row built. No gap is recorded here.

Rows 13 and 36 are UNVERIFIED as closed. At `6cb503a` jayzee's PARITY.md still says `Status: partial` for both, with the open clauses quoted below. Row 36 no longer lists the host GC observer as open, because jayzee ports it as `src/telemetry-pure/gcObserver.js`.
